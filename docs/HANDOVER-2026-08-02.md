### The build trap, which has cost real time twice

A bare `cargo build -p astroctl-field` **succeeds and silently produces a binary that refuses both
real devices** — it dies at startup with "this build of astroctl has no libgphoto2 support", and the
mount half is worse because construction succeeds and only `connect` fails. Neither `libgphoto2-dev`
nor `libudev-dev` is installed system-wide and there is no root on this machine, so both are staged
by hand:

```bash
set -a; . <scratchpad>/gp-env.sh; set +a
export PKG_CONFIG_PATH="$PKG_CONFIG_PATH:<scratchpad>/pc"
cargo build -p astroctl-field --bin astroctl-field --features libgphoto2,serialport
```

Verify before restarting the node — **both must print 0**:

```bash
strings target/debug/astroctl-field | grep -c "has no serial port implementation"
strings target/debug/astroctl-field | grep -c "has no libgphoto2 support"
```

The PWA is embedded via `include_dir!` at compile time, so **any** frontend change needs this
rebuild plus a node restart — which is exactly when the trap fires. Stop the old node by PID from
`ss -tlnp`, never with `pkill -f` (the pattern matches the invoking shell's own command line).

## 3. The open thread: Layer 2 collision geometry

`crates/astroctl-safety/src/rig.rs` models the rig as a capsule along the optical axis and the
tripod as a truncated cone, and `SafeMount` refuses a slew with `LIMIT_COLLISION` when they meet.
`mount.geometry` is **absent by default**, so the limit does not exist on any current node and
nothing today is affected by what follows.

**It does not work.** Fed the operator's measurements it refuses 91% of the sky above the horizon;
with every questionable number corrected in the model's favour it still refuses 68%. That is a
modelling failure, not a measurement one.

### What is established

- A sphere centred *on* the declination axis is invariant under rotation about it, so it cannot see
  a declination slew at all. Ruled out early; the capsule replaced it.
- A *solid* cone refuses the zenith, because the volume between the legs is free space — it is where
  the counterweight hangs. The obstacle is the cone's lateral surface.
- The cone treats a 2–6% obstacle (three ~30 mm legs on a circumference of 1.5–4.4 m) as 100% solid:
  an over-detection factor of roughly **28×**.

### Where it stands

The last diagnostic, for the tube at the zenith with the operator's numbers:

| | |
|---|---|
| tube's lower end | 300 mm below the axes, 180 mm out |
| leg surface at that height | 241 mm out |
| gap | 61 mm — less than any realistic tube radius, so: refused |

One of three things is false and the operator can see which: that the tube's lower end is really
300 mm below the axes; that the legs are really 241 mm out there; or that they nearly touch, which
they evidently do not since the zenith is reachable in practice.

**The assistant's hypothesis was `top_radius_mm`** — 200 mm implies a 400 mm top plate where an
HEQ5's is 100–120 mm across, and that single number sets where the cone starts. **The operator
rejected the leg-discretisation diagnosis and asked for the cone to be kept.** That disagreement is
unresolved and is the first thing to settle.

### Recommendation

Start Layer 2 again from a clean session with the measurements settled first, and with a survey test
that reports the refused fraction of the sky **before** the model is trusted. The target is
single-digit percent. The assistant was wrong twice on this geometry (sphere, then cone) and
patching further from the same context is not the cheapest path to a correct model.

Not modelled at all: the **counterweight shaft and weights**, which swing on the other side of the
declination axis and are a genuine hazard during right-ascension motion. A second capsule; nobody has
measured the shaft.

## 4. Hardware facts that outrank the documentation

**The home hour angle is +6h, not 0** (M3-T06, verified twice on the mount). Both counters at
`0x800000` means the tube is six hours west of the meridian, not on it. The four-line mech↔sky model
in `skywatcher/math/mech.rs` is the authority.

**Manual slew stalls above the speed-class crossover.** E11, by ear: 1× and 8× turn, 64× ramps up
and jams. The counter reports the motion it did not make, so nothing in software can see a stall —
the operator's ears are the only rotor sensor in the system. The crossover on this mount is at
`f/r = 16`, i.e. **38.8× sidereal**: everything heard to turn is below it and programs in the low
class, and the rate that jammed is above it in the high class. A *goto* was measured cruising at
835× in that same high class, so the suspicion is that this mount will not **start an unbounded slew
in the high class**, and that the ceiling is not a rate at all.

*The experiment that would settle it, ten minutes by ear:* drive 32×, then 39× — either side of the
crossover, a 20% rate change across a class change. If the jam follows the class rather than the
rate, the fix is to ramp the start rather than cap the ladder, and fast manual slewing comes back.

**Polar alignment is unverified and probably wrong.** At mechanical declination 60 the operator
observed the tube ~2° from the zenith. At Vilnius (54.7°) it should be 5.3° off; at 59.9° it would be
0.1° off. That implies the latitude wedge is set to roughly 58–60°, which would be 4–5° of polar
misalignment and would dominate every pointing error. A straight-on photograph of the latitude scale
was requested and not supplied. **Settle this before trusting any goto accuracy measurement.**

**The mount can drive itself into the tripod and has done.** 2026-08-01: a goto computed through the
then-broken map put the tube into a tripod leg. The rules that came out of it are in
`spikes/skywatcher-heq5/FINDINGS.md`; the operator's eyes remain the only position sensor.

## 6. Notes on method that were paid for

**A null result from an instrument that cannot observe the thing is not a null result.** This has
cost the project three times now: an SSH key declared absent by a test that had disabled the agent
holding it; the mount watchdog declared silent because the assistant grepped the tracing log when
alerts go to `events.jsonl` (it had fired correctly six times); and a "no failures" test run reported
green when the test binary had not compiled and the suite never ran. **Count compile errors
separately from test failures.**

**Verify agent claims rather than relaying them.** Every subagent result this session was re-run
independently before being reported. They held up, which is the reason to keep doing it cheaply
rather than the reason to stop.

**Do not fit the rig to the test.** An early Layer 2 test asserted "the zenith must be clear" against
tripod numbers nobody had measured. Assert properties that hold for any consistent rig — symmetry,
which obstacle is reported, that the mechanical pose and not just the pointing decides the verdict.

**Record corrections rather than applying them quietly.** SDD §5.4.2 carries two corrections found by
implementing it, including one where the documented design would have reproduced the very defect it
was written to fix.
